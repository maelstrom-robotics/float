# Contributing

We're a small team, so we use AI tools a lot. That's fine. A few rules keep it from turning into a mess:

1. **Understand what you push.** Judges question us about our design and who built what in the engineering presentation. If you can't explain it, don't merge it.
2. **Small changes.** One feature or fix per pull request. Say what it does and how you tested it.
3. **Test before "done".** On the real hardware, or with fake sensor data if the hardware isn't here yet.
4. **No direct pushes to `main`.** Open a pull request and get one review.
5. **Write down decisions.** If we pick a board, sensor or approach, add a short note in `docs/` saying what and why. It goes straight into our technical documentation later.
6. **Share what works.** If a prompt or tool worked really well, post it in #software.

## Getting started

1. Ask in #software to be added to the GitHub org.
2. Clone this repo, make a branch, open a PR.
